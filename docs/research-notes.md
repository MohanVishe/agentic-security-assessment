# Research notes

What was checked before the build (October 2026) and the decision each finding led to.

## Scanners: how to run them headless, and what they output

| Tool | How it runs here | Output used | Notes |
|---|---|---|---|
| nmap | `nmap -Pn -sT -sV -T4 -p <top 100 + target port> -oX -` | XML, parsed with the standard library | `-sT` (connect scan) needs no raw sockets, so the container runs unprivileged. nmap has no JSON output. |
| OWASP ZAP | Daemon container, driven over its REST API: new session, spider, AJAX spider, wait for the passive scanner, read alerts | JSON alerts (`/JSON/alert/view/alerts/`) | Equivalent to `zap-baseline.py -j`: no active attacks. The AJAX spider matters for single-page apps: on Juice Shop the plain spider found 4 alert types, with the AJAX spider 9. |
| Nuclei | `nuclei -u <url> -jsonl -o <file> -t http/technologies -t http/misconfiguration -t http/exposures -t http/exposed-panels -exclude-tags intrusive,dos,fuzz,brute-force,default-login` | JSON Lines, one result per line | Results are written as they are found, so a timed-out run still yields findings. Some templates carry a CVSS score and vector under `info.classification`. |
| Nikto | `nikto.pl -h <url> -Format json -maxtime 120s -nointeractive` | JSON | Needs Perl with `Net::SSLeay` and `XML::Writer`. Does not rate findings. A run cut off by `-maxtime` can leave a trailing comma, which the parser repairs. |

Sources: [ZAP baseline scan](https://www.zaproxy.org/docs/docker/baseline-scan/), [ZAP API](https://www.zaproxy.org/docs/api/), [Nuclei docs](https://docs.projectdiscovery.io/opensource/nuclei/overview), [Nikto](https://github.com/sullo/nikto), [nmap reference](https://nmap.org/book/man.html).

**Decision:** one small HTTP service wraps the three CLI tools and talks to the ZAP daemon. Each wrapper returns the same finding shape so the agents never parse a native format.

## Langflow

- Current release: **1.12.5**. Custom components now import from `lfx` (`lfx.custom.custom_component.component`, `lfx.io`, `lfx.schema.message`).
- `LANGFLOW_COMPONENTS_PATH` loads custom components from `<path>/<category>/` with an `__init__.py`.
- `LANGFLOW_LOAD_FLOWS_PATH` imports flow JSON files at startup (requires `LANGFLOW_AUTO_LOGIN=true`). A flow's `endpoint_name` can be used in place of its ID.
- A flow is run with `POST /api/v1/run/{flow_id_or_endpoint_name}` and an `x-api-key` header. The reply text is at `outputs[0].outputs[0].results.message.text`.
- API requests need a key even with auto-login. `LANGFLOW_API_KEY_SOURCE=env` plus `LANGFLOW_API_KEY` sets one shared key from the environment, which avoids creating a key by hand in the UI.

Sources: [run flow API](https://docs.langflow.org/api-flows-run), [API keys and authentication](https://docs.langflow.org/api-keys-and-authentication), [custom components](https://docs.langflow.org/components-custom-components), [environment variables](https://docs.langflow.org/environment-variables).

**Decision:** three custom components, one per agent, wired in a line. The flow file is generated by `langflow/build_flow.py` from Langflow's own component catalog so it is reproducible, and it stays editable in the canvas.

## LLM: Groq free tier

- `llama-3.3-70b-versatile` was deprecated on 16 August 2026. Groq's suggested replacements are `openai/gpt-oss-120b` and the Qwen 27B line, now `qwen/qwen3.8-27b`.
- All Groq-hosted models support tool calling. `qwen/qwen3.8-27b` also supports parallel tool calls; `openai/gpt-oss-120b` does not.
- Free-tier limits for both: 30 requests/minute, 1,000 requests/day, 8,000 tokens/minute, 200,000 tokens/day, counted per organization.

Sources: [Groq deprecations](https://console.groq.com/docs/deprecations), [Groq rate limits](https://console.groq.com/docs/rate-limits), [Groq tool use](https://console.groq.com/docs/tool-use).

**Decision:** default to `openai/gpt-oss-120b`. The 8,000 tokens/minute limit is the binding one, so the agents are given summaries and titles, never raw scanner output. The provider is any OpenAI-compatible endpoint, set by three environment variables, with an optional fallback provider for rate limits.

## Severity and remediation

- CVSS v3.1 and v4.0 use the same qualitative scale: None 0.0, Low 0.1–3.9, Medium 4.0–6.9, High 7.0–8.9, Critical 9.0–10.0.
- ZAP rates alerts High / Medium / Low / Informational and supplies a CWE, a solution text and references. Nuclei templates carry a severity and sometimes a CVSS score and vector. Nikto and nmap give no rating.
- A CVSS score needs the full vector (attack vector, complexity, privileges, impact...). A scanner alert alone does not contain enough to compute one.

Sources: [CVSS v3.1 specification](https://www.first.org/cvss/v3-1/specification-document), [CVSS v4.0](https://www.first.org/cvss/v4.0/).

**Decision:** use the scanner's CVSS score when it gives one; otherwise map the scanner's own rating to the band of the same name and say so on the finding. The LLM never assigns a score. Remediation is shown in two labelled parts: the scanner's own solution text, and AI-written guidance.

## Existing agentic pentest projects

- **PentestGPT** splits work into reasoning, generation and parsing modules and keeps a Pentesting Task Tree so the model does not lose the overall state.
- **PentAGI** uses an orchestrator with researcher, developer and executor agents running tools in isolated containers.
- **ARTEMIS** adds a triage module that checks findings before they reach the report.
- Common lessons: separate planning from execution, keep tool output out of the planner's context, validate tool arguments outside the model, and require a logged authorization before the loop starts. Scanner output is untrusted text and can carry prompt injection.

Sources: [PentestGPT paper](https://arxiv.org/abs/2308.06782), [PentestGPT](https://github.com/GreyDGL/PentestGPT), [PentAGI](https://github.com/vxcontrol/pentagi), [OWASP LLM01 Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/).

**Decision:** Planner / Executor / Reporter, with the target and the authorization check held outside the LLM in the tool service.
